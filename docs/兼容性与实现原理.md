# 兼容性与实现原理

本文档解释：为什么这样实现、哪些输入法能用、不能用的怎么改、以及开发时踩过的坑。

## 一、三条实现路线

想让"打错的拼音变中文"，本质上只有三条路：

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 选中回改（本项目） | 把拼音**重新喂给系统输入法** | 候选质量=你平时打字；免费拿到词库/云候选/调频；实现小 | 依赖输入法的全拼方案与切换键；需要模拟按键 |
| B. 自己转（词典/模型） | 用 `pinyin2hanzi`、HMM 或 LLM 直接转 | 不依赖输入法 | 没有"候选逐个选"的体验；多音字/新词差；要自己做候选窗 |
| C. 改输入法本身 | 写一个 TSF/IBus 输入法 | 最干净 | 工程量大几十倍；用户要换输入法 |

已有的相关项目：UnimeType、ds-input（B/C 路线，整句 AI 转换、无候选）；Quicker「输入还原为中文」、Chrome 扩展 `pinyin-to-chinese`（A 路线，但前者需要 Quicker，后者只限网页）。

本项目选 A 路线，并且**不依赖任何商业软件**。

## 二、A 路线的关键点

### 1. 怎么读选区

用剪贴板哨兵法：

1. `ClipboardAll()` 保存用户原本的剪贴板
2. 写入一个唯一哨兵字符串
3. 发送 `Ctrl+C`
4. 轮询剪贴板最多 800ms，内容变了说明复制成功
5. 读完恢复原剪贴板

比 UIA（`TextPattern.GetSelection`）兼容性更好（UIA 在部分 Electron/Qt/终端控件里读不到），代价是极少数应用里 `Ctrl+C` 有副作用（终端里跑程序时是中断信号）→ 用黑名单规避。

### 2. 怎么判断选中的是拼音

不能只判断"是不是 ASCII 字母"，否则 `hello world` 会被当拼音。做法：

- 小写化、去数字/标点，分隔符转空格
- 含空格时：每个 token 必须在 **419 个标准音节表** 里（`ni hao shi jie` ✅，`hello world` ❌）
- 不含空格的长串：动态规划切分成合法音节（`womingtianqubeijing` ✅）
- 长度限制 2–64 个字母

代价：**拼音必须拼对**。如果你打的是简拼（`wmtqbj`）或错拼音，工具会当作"不是拼音"忽略——这是有意的，宁可漏转不可误转。

### 3. 怎么判断输入法现在是中文还是英文

优先级从高到低：

1. **IMM32 方法**：`ImmGetDefaultIMEWnd(前台窗口)` 拿到 IME 窗口，再 `SendMessageTimeout(imeWnd, WM_IME_CONTROL(0x0283), IMC_GETCONVERSIONMODE(0x0001))`，返回值的 bit0 = 是否中文。
   - 优点：跨进程安全、带超时（400ms）、对**所有 IMM32 感知的 IME** 有效（微软拼音实测返回 1025=中文、0=英文）。
2. **AttachThreadInput + ImmGetContext**：对部分老式控件有效，但 `ImmGetContext` 要求调用线程拥有窗口，跨线程/进程经常返回 0。
3. **读不到**：走 `AssumeNative=1` 兜底——假定你按的触发键已经把输入法切回中文了。这是 Shift 类输入法的常见情况，所以默认可用。

> ⚠️ 开发时最大的坑：一开始只用 `ImmGetContext`，在别的进程窗口上永远返回 0，导致工具"以为读不到状态"。加上 `ImmGetDefaultIMEWnd` 方案后记事本/文本框才正常。

### 4. 怎么保证补切后确实是中文

- 若读到"英文态"：先发一次 `ToggleKey`（默认模拟 LShift 单击），等 240ms 再读一次
- 还是英文：尝试 `ImmSetConversionStatus(hIMC, conv|IME_CMODE_NATIVE)`
- 仍然失败：放弃并提示（不会乱打字母破坏你的文本）

### 5. 怎么区分"单按 Shift"和"Shift+方向键选字"

注册一组 `~*` 全局热键（字母/数字/方向键/鼠标键等），在 Shift 按住期间只要有任何一个被按下就打标记 `g_otherKey=true`，抬起时不触发。所以：

- 选中文本后**单按** Shift → 触发
- `Shift+方向键` 选字、`Shift+点击` 选字、`Shift+其它键` → 不触发
- 长按 >320ms → 不触发

## 三、适配各类输入法

### 微软拼音 / 搜狗 / 微信 / QQ 拼音 / 百度（默认 Shift 切中英）

开箱即用，`ToggleKey=LShift`。注意搜狗/微信等有"**按应用记住中英状态**"选项，关掉后行为更可预测。

### 微软拼音改成 Ctrl+Space 切换

`设置.ini`：

```ini
[ime]
ToggleKey=Ctrl+Space
```

用户操作仍然是"选中 → 单按 Shift"：Shift 不切输入法，工具检测到英文态后自己补发 Ctrl+Space 再回灌。

### 中英是两套键盘布局（英文键盘 + 中文输入法）

这时"英文状态"根本不是输入法的英文模式，而是另一个键盘布局，Shift 切不回来。配置：

```ini
[ime]
ToggleKey=Ctrl+Shift      ; 或 Win+Space，取决于你的切换方式
RequiredLangId=0x0804     ; 简体中文
```

工具会先检查前台键盘布局语言 ID，不是中文就先发 `ToggleKey` 切回来（最多试一次，失败就提示，不会硬打）。

### 双拼 / 五笔为什么不行

回灌的是**全拼字母串**。双拼输入法会把每个字母当声母/韵母键解析（`wo` 会被理解成两个键位），五笔要的是字根编码。这类方案要么改输入方案为全拼，要么改用 B 路线（自己做转换引擎）。

## 四、已知坑（开发记录）

| 坑 | 现象 | 处理 |
|---|---|---|
| `ImmGetContext` 跨进程失效 | 永远返回 0，误判"读不到状态" | 改用 `ImmGetDefaultIMEWnd + WM_IME_CONTROL` |
| WinForms/IMM32 老控件数字选候选不生效 | 回灌后按 1/2 不上屏，空格可以 | 文档说明；真实应用（记事本/浏览器）正常 |
| 输入法注入按键与用户物理按键混在一起 | 回灌的字母可能触发工具自己的热键 | `g_busy` 门闩 + AHK 自身注入的按键默认不触发自身热键 |
| 管理员窗口收不到注入 | 按了没反应 | 工具需以管理员身份运行（UIPI 限制） |
| 选区读取占用剪贴板 | 极短时间剪贴板内容变化 | 读完立即恢复；`ClipboardAll` 保留全部格式 |
| 测试时误伤已有记事本窗口 | Win11 记事本会恢复上次会话，测试脚本可能选中用户正在编辑的窗口 | 验证脚本一律自建窗口，见 `tools/` |
